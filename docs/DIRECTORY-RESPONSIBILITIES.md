# Directory Responsibilities

这份文档用于说明仓库中几个关键目录各自承担什么职责，以及它们与 GitHub、npm 包和用户项目之间的关系。

目标不是解释每个文件，而是先把目录边界讲清楚，避免内容再次混层。

## 核心原则

一个目录只回答一种问题：

- 这是仓库自己的公开说明
- 这是工具运行时需要的资产
- 这是会初始化到用户项目里的资产
- 这是仅供本地保留的私有沉淀

如果一个目录同时承担多个角色，后续就很容易再次混乱。

## 目录职责总表

| 目录 | 主要服务对象 | 是否进入 GitHub 源码 | 是否进入 npm 包 | 是否进入用户项目 |
|---|---|---|---|---|
| `docs/` | 仓库公开文档 | 是 | 否 | 否 |
| `guides/` | 使用工具的开发者与模型 | 是 | 是 | 是，由 `init` 复制到项目根目录 |
| `scaffold/docs/` | 用户项目初始化文档骨架 | 是 | 是 | 是，由 `init` 复制到项目的 `docs/` |
| `templates/` | CLI 运行时模板资产 | 是 | 是，仅打包必需模板 | 否，按命令生成内容 |
| `src/` | CLI 与规则引擎实现 | 是 | 是 | 否 |
| `website/` | 公开站点源码 | 是 | 否 | 否 |
| `thinking/` | 本地私有沉淀 | 否，已被 `.gitignore` 忽略 | 否 | 否 |

## `docs/`

`docs/` 是仓库自己的公开文档层。

它回答的是：

- 这套系统的公开方法论是什么
- 哪些理念适合对外保留
- 每个公开版本交付了什么

它不应该承担：

- 用户项目运行时资产
- npm 随包指南
- 私有思考和实施判断

当前这一层应尽量保持克制，只保留适合出现在公开源码中的内容。

## `guides/`

`guides/` 是给开发者和模型直接使用的操作指南层。

它回答的是：

- 模型应该如何进入项目
- 模型应该如何读取和更新文档
- 模型在不同阶段应该采用什么工作模式
- 可以直接复用哪些 prompt

这一层会：

- 进入 GitHub 源码
- 进入 npm 包
- 由 `vibedocs init` 默认复制到用户项目根目录

所以它的定位是：

**既是随包资产，也是用户项目里的 agent 工作手册。**

## `scaffold/docs/`

`scaffold/docs/` 是用户项目文档系统的初始骨架。

它回答的是：

- 一个新项目最开始应该长出哪些文档
- 各类文档的默认起步结构是什么

这一层会：

- 进入 GitHub 源码
- 进入 npm 包
- 被 `vibedocs init` 复制到用户项目的 `docs/`

所以它的定位是：

**面向用户项目的工作文档起点。**

## `templates/`

`templates/` 是 CLI 运行时使用的模板资产。

它主要用于：

- `feature create`
- 其它按模板生成文件的命令

这一层不是给人长期阅读的文档区，而是工具依赖的模板资源。

因此只会把运行时真正需要的模板打进 npm 包，而不是整个目录原样发布。

## `src/`

`src/` 是实现层。

它回答的是：

- CLI 如何运行
- 规则引擎如何检查
- semantic audit 如何工作
- 报告如何生成

这一层进入 GitHub，也进入 npm，但不会被复制到用户项目。

## `website/`

`website/` 是公开站点源码。

它服务的是：

- 产品介绍
- 使用说明
- 对外文档站

这一层进入 GitHub，但不进入 npm，也不进入用户项目。

## `thinking/`

`thinking/` 是本地私有沉淀层。

它适合存放：

- 理念推演
- 路线判断
- 产品边界思考
- 实施计划
- 实现解读
- 过程性结论

这一层不会：

- 进入 GitHub
- 进入 npm
- 进入 GitHub Pages
- 进入用户项目

它存在的意义，就是把“公开文档”和“个人沉淀”明确分开。

## 放置判断规则

如果以后不确定一个文件应该放哪，优先按这 4 个问题判断：

1. 这是给谁看的？
2. 这是不是工具运行时必需资产？
3. 这是不是用户项目初始化后必须直接拿到的内容？
4. 这是不是只属于本地思考或过程判断？

可以直接套用下面这条简化规则：

- 仓库公开说明：放 `docs/`
- 给用户和模型直接操作：放 `guides/`
- 给用户项目初始化：放 `scaffold/docs/`
- 给工具运行：放 `src/` 或必需 `templates/`
- 给自己保留：放 `thinking/`

## 一句话结论

`docs` 是仓库公开文档，`guides` 是随包且进项目的 agent 指南，`scaffold/docs` 是用户项目的初始工作文档，`thinking` 是本地私有沉淀。
