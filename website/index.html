Open-source docs toolkit

VibeDocs keeps project documentation understandable.

VibeDocs is built for teams whose docs start useful, then drift as the product changes. It gives you a repeatable structure, feature-level document packages, and local checks so humans and AI tools can work from the same context.

Start in 5 minutes View repository
CLI: vibedocs Package: @leapx-ai/vibedocs License: Apache-2.0
What you get

Structure, feature packages, and local checks.

Docs scaffold Generate a Minimal, Standard, or Full docs tree inside the repository.
Feature packages Create scoped document sets for PRD, spec, acceptance, analytics, and more.
Local checks Run audit and glossary check before drift spreads through the repo. 
npm install @leapx-ai/vibedocs
npx vibedocs init --mode minimal
npx vibedocs audit --format json
Why it exists

Built for projects where docs drift faster than code.

When context lives across README fragments, issue threads, chats, and stale specs, teams keep repeating the same explanations and AI tools work from outdated context.

Scattered context

Information is hard to find and harder to trust

Product decisions, technical intent, and delivery status end up split across unrelated files, tickets, and conversations.

Ad-hoc structure

Each project reinvents the docs system from scratch

Without a shared structure, it is hard to know which document should exist, what belongs in it, and what should stay out.

Drift after launch

Docs are created once, then stop reflecting reality

Even good documents lose value quickly if nobody has a lightweight way to update and check them during normal development.

What it provides

A docs system you can adopt inside an existing repo.

VibeDocs stays close to plain files. You do not need a hosted platform or a new editor to make documentation more structured and maintainable.

Templates

Reusable document starters

Start from opinionated templates for governance, product, engineering, delivery, operations, and feature-level documentation.

Scaffold

A docs tree you can drop into a repo

Generate a Minimal, Standard, or Full structure so the first version of the docs system is created consistently instead of by hand.

CLI

Local commands for setup and checks

Use init, feature create, audit, and glossary check to keep documentation practical and current.

How to start

Three steps are enough for the first run.

1. Install

Add the public package to your repository and use the local binary.

npm install @leapx-ai/vibedocs

2. Generate docs

Initialize a baseline docs system, then add focused packages for real features.

npx vibedocs init --mode minimal
npx vibedocs feature create focus-mode

3. Keep it aligned

Run audits and glossary checks as part of daily development, not just at release time.

npx vibedocs audit --changed src/app.js
