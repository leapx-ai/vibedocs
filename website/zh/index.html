开源文档操作层

让文档在第一次上线之后依然持续有用。

VibeDocs 把零散 Markdown 提升为一套文档操作系统： 可复用模板、项目 scaffold、本地 CLI，以及一套之后可继续喂给付费工作流的共享规则引擎。

产品结构

开源层负责起步，付费层负责持续约束。

免费层解决的是“如何把文档系统跑起来”，付费层解决的是“如何在团队协作中不继续烂掉”。 两者边界要清楚，但规则语义必须保持连续。

工作方式

先把文档系统建起来，再用规则阻止它漂移。

1. 初始化

从 scaffold 生成 Minimal、Standard 或 Full 文档骨架。

npx vibedocs init --mode minimal

2. 按功能扩展

为复杂功能生成功能包，补齐 PRD、线框流、技术说明、验收与埋点。

npx vibedocs feature create focus-mode

3. 持续巡检

在本地用 diff-aware audit 找出建议更新的文档触点，再决定要不要进入提交流程。

npx vibedocs audit --changed src/app.js
为什么有效

它约束的是结构和职责，不是你的技术栈。

文档角色 × 生命周期

文档不是一堆平铺文件，而是按角色和生命周期阶段组成矩阵，这样上下文才能长期可维护。

SSOT 先声明再协作

如果没有明确单一事实源，团队和 AI 都会在多个文件里重复维护状态，最后只剩漂移和冲突。

规则只保留一套语义

本地 audit、未来的 PR 检查和自动巡检应该共享同一套规则结果，而不是各写一份相似逻辑。

公开文档边界

这个站点是公开产品层，不是内部规划库。

这里承载的是安装方式、CLI、概念和 schema。内部策略判断、商业化细节和未公开路线不应该直接映射到站点内容。
