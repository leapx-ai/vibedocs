开源文档工具包

VibeDocs 让项目文档保持可理解。

它为那些文档一开始有用、但随着产品迭代很快失真的团队而生。 VibeDocs 提供可重复的文档结构、功能级文档包和本地巡检，让人和 AI 都能基于同一套上下文工作。

5 分钟上手 查看仓库
CLI: vibedocs Package: @leapx-ai/vibedocs License: Apache-2.0
你会得到什么

结构、功能包与本地巡检。

文档骨架 在仓库内生成 Minimal、Standard、Full 三档文档结构。
功能包 为具体功能生成 PRD、技术说明、验收与埋点等成组文档。
本地巡检 用 audit 和 glossary check 在漂移扩散前发现问题。 
npm install @leapx-ai/vibedocs
npx vibedocs init --mode minimal
npx vibedocs audit --format json
它为了解决什么问题而生

当上下文分散、文档失真时，协作成本会持续上升。

当信息散落在 README、需求记录、聊天和过期说明里，团队会不断重复解释， AI 也会基于陈旧上下文工作。

上下文分散

信息难找，也更难确认是否可信

产品决策、技术意图和交付状态散落在不同文件、任务单和对话里，很难形成稳定上下文。

结构临时拼装

每个项目都在重新发明一套文档系统

如果没有统一结构，就很难知道哪些文档应该存在、各自写什么，以及哪些内容不该混在一起。

迭代后失真

文档生成一次后，很快就不再反映真实情况

即使一开始写得不错，如果没有低成本的更新和检查手段，文档价值也会快速下降。

它提供什么能力

一套可以直接放进现有仓库的文档系统。

VibeDocs 尽量贴近普通文件工作流。你不需要迁移到托管平台，也不需要学习新的编辑器。

Templates

可复用的文档起步模板

从治理、产品、工程、交付、运营到功能包，直接复用一套结构明确的文档模板。

Scaffold

可以直接落仓库的目录骨架

通过 Minimal、Standard、Full 三档目录骨架，快速把第一版文档系统生成出来。

CLI

本地初始化与巡检命令

用 init、feature create、audit、 glossary check 让文档持续可维护。

如何开始使用

第一次跑通，先做这三步就够了。

1. 安装

把公共包装进仓库，使用本地命令开始操作。

npm install @leapx-ai/vibedocs

2. 生成文档

先建一套基线文档，再按真实功能继续扩展。

npx vibedocs init --mode minimal
npx vibedocs feature create focus-mode

3. 保持对齐

把 audit 和 glossary check 变成日常动作，而不是拖到发布前再补。

npx vibedocs audit --changed src/app.js
